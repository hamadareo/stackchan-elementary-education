# StackChan × Sokutsu(即通)

小学生向けに、M5Stack **StackChan(CoreS3)** を「しゃべる・見る・遊べるロボット」として使うためのシステムです。
ロボット本体は **耳(マイク)・口(スピーカー)・顔(画面)・目(カメラ)・首** だけの薄い端末で、
聞き取り・翻訳・会話・ゲームの進行など重い処理は、すべてパソコン側の **ブリッジ** が行います。

- 教室では **USB の有線のみ**(Wi-Fi なし)で、3 台を 1 台のパソコン(Ubuntu)につなぎ、先生が管理アプリで操作します。
- 機器どうしは連携せず、**1 台ずつ独立**して遊びます。
- 授業モードの間、ロボットは **先生がボタンを押すまで何も話さず、何もしません**。

## できること

### 遊び(6 つ)— 先生が管理アプリの「授業」タブで開始・中止

| 遊び | 内容 |
|---|---|
| しりとり | ロボットから始める。ことばの吹き出しと、最後の字を赤く表示 |
| じゃんけん | 声、またはカメラに手をかざして判定。出した手を画面に大きく表示 |
| なぞなぞ | 5 問。ヒント・「わからない」にも対応 |
| おみくじ | 「ガラガラ…」のあと運勢とラッキーカラーを表示 |
| ものまねボイス | いろいろな声の調子で言葉をまねする |
| ずんだの チャリはしり | 画面の中で自転車のずんだもんが走り、いわ・コーン・はこをよける(下記) |

どの遊びも、機器の画面に絵(吹き出し・手・札・○×など)が出ます。押した瞬間に顔と画面が変わり、「中止」は声も含めてすぐ止まります。
カメラを使う遊びでは、近すぎる・遠すぎる・暗いときに、ロボットが「すこしさがってね」などと子どもに教えます。

### ずんだの チャリはしり
ゲームの描画・物理は **機器側(ファームウェア)** で動き、ブリッジは開始・中止・実況・記録を担当します。

- ジャンプの入力は 6 通り: **画面タッチ / 天面(頭のてっぺん)タッチ / 実際のジャンプ(カメラ)/ 声の「ジャンプ」/ ジョイスティック / 先生が管理アプリで代わりに押す**
- ぶつかると、走った距離(メートル)とベスト記録をずんだもんが実況。タッチかジャンプで再スタート。
- ゲームは 1/60 秒の固定刻みで進むため、描画が遅れても速さは実時間のまま。描画が重いときは雲・山を省いて軽くします。
- 機器の画面のコマ数と「処理おち」の疑いは、管理アプリに表示されます。
- 機器との接続が約 6 秒切れたままなら、ブリッジは遊びを終えて「接続が切れました」と表示します。
- からだジャンプ: カメラで顔の高さの変化を見て検出(`bridge/bodyjump.py`)。ゲーム中はカメラを小さく・多めに送ります。

### ゲームパッド(USB)
USB のゲームパッドをつなぐと自動で使えます(`/dev/input/js*`)。左スティックと十字キーは、下の表のスティックと同じ操作です(十字キーは倒す量がないので、首はゆっくり一定の速さ)。
ボタンは、遊びごとに決まっています。

| 遊び | ボタン 1 / 2 / 3(番号 0 / 1 / 2) |
|---|---|
| チャリはしり | どのボタンでもジャンプ |
| じゃんけん | ぐー / ちょき / ぱー |
| おみくじ | やる / やめる |
| なぞなぞ | ヒント / わからない |

### ジョイスティック(Arduino)
アナログスティックを付けた Arduino UNO を **hamada の USB** に挿すと、ブリッジが自動で見つけます(StackChan の ESP32 とは USB の ID で区別)。

| 状況 | 操作 |
|---|---|
| チャリはしり | どの向きでも「ぐいっ」と倒す / ボタン = ジャンプ(倒しっぱなしでは連続しない) |
| じゃんけん | 左=ぐー / 上=ちょき / 右=ぱー |
| おみくじ | ボタン=やる / 下=やめる |
| なぞなぞ | ボタン=ヒント / 下=わからない |
| 待機中(遊んでいない機器) | 倒した向きへ、首が動く(動かしている間と、そのあと約 4 秒は顔追従を止める) |

しりとり・ものまねは声だけです。操作は、その遊び(待機)をしている機器すべてに送られます。
首の向きが逆なら、環境変数 `SC_JOY_PAN_SIGN` / `SC_JOY_TILT_SIGN` を `-1` にします。

- スケッチ: `arduino/joystick/joystick.ino`(配線: GND→GND、+5V→5V、VRx→A0、VRy→A1、SW→D2)。
- 書き込み: Arduino IDE、または `arduino-cli compile/upload --fqbn arduino:avr:uno`。
- つながっているかは、管理画面の「授業」タブに表示されます。実装は `bridge/joystick.py`。

### そのほか
- 日本語⇄英語などの通訳(文ごとのストリーミング再生、話速の自動調整)、顔追従(待機中も常に)、見回し、電池・ゆすり検知。
- 管理アプリ(Qt)とブラウザ版の管理画面(音量・言語・授業・機器の画面・記録)。
- 先生の入力欄(聞き取れないとき、子どもの代わりに答えを入れる)。
- 機器の自動登録(機器 ID で識別。USB の差し口は問わない)、USB 経由でのファーム一括更新。

## 構成

```
StackChan(CoreS3) ×3                         hamada(Ubuntu) = ブリッジ + 管理アプリ
 マイク  ─ PCM16 16kHz ─┐                      ┌ 聞き取り / 翻訳 / 声(VOICEVOX)
 カメラ  ─ JPEG ────────┼─ USB シリアル ──▶    ├ 顔検出(YuNet)・手の検出・からだジャンプ
 タッチ・IMU・電池 ─────┘   (Wi-Fi も可)       ├ 遊びの進行(しりとり ほか)・授業の制御
 ◀ 表情 / 字幕 / 画面ボード / 首 / 声 ───────   └ 管理画面(HTTP :8080)+ Qt 管理アプリ
                                               s109(GPU サーバー)があれば優先、なければ単体で動く
```

| ディレクトリ | 内容 |
|---|---|
| `firmware/` | 端末のファームウェア(PlatformIO / Arduino / M5Unified / m5stack-avatar を改造)。`lib/M5Stack-Avatar/src/Balloon.h` に画面ボードとチャリはしりの描画 |
| `bridge/` | ブリッジ(Python)。`stackchan_bridge.py` が本体、`lesson.py` が授業の制御、`shiritori.py` `janken.py` `quiz.py` `fun.py` が遊び、`board.py` が画面ボード |
| `app/` | 管理アプリ(PySide6)。`lesson_ui.py` が授業タブ |
| `deploy/` | Ubuntu への配備(systemd ユニット、`deploy.sh`)、macOS の launchd |
| `tools/` | 機器の初期設定・一括更新・集計・報告書の生成 |
| `tests/` | 単体テストとシミュレーション(`sim_lessons.py`) |
| `docs/ONSITE.md` | **先生向け**の現場手順 |
| `SETUP.md` | 環境構築の詳細(Mac / Ubuntu / ファーム) |

## クイックスタート

### 1. ブリッジ
```bash
cd bridge
python3.10 -m venv .venv && .venv/bin/pip install -r requirements.txt
bash fetch_models.sh                 # 顔検出モデル(YuNet)などを取得
bash run.sh                          # s109 が使えれば優先、だめなら手元で完結
bash run.sh --engine mac             # 手元だけで動かす
```
Sokutsu(`tsuyaku`)の部品を使うため、`TSUYAKU_REPO` で場所を指定します(詳細は `SETUP.md`)。

### 2. ファームウェア
```bash
cd firmware
cp src/config.h.example src/config.h        # Wi-Fi・OTA パスワードなど(config.h は git 管理外)
pio run -e m5stack-cores3                    # ビルド
pio run -e m5stack-cores3 -t upload          # USB で書き込み
```
初回は `SERVO_ENABLE 0` で顔・音声・字幕だけ確認し、サーボのピンと可動域を確かめてから `1` にします。

### 3. 配備と更新(Mac → Ubuntu)
```bash
bash deploy/ubuntu/deploy.sh                 # ブリッジと管理アプリを配って再起動(約 15〜20 秒)
```
その後、管理アプリの「機器」タブの **「USB の機器を更新する」** で、つながっている機器が 1 台ずつ(約 1 分)更新されます。
更新中は USB を抜かないでください。管理アプリ(Qt)の画面は、配備後に手動で再起動します。

### 3b. 新しい Ubuntu PC を足す(自動セットアップ)
```bash
bash deploy/ubuntu/setup_host.sh <ssh の宛先> <機器名の頭>      # 例: setup_host.sh latitude Lat
```
hamada の環境を Mac 経由で配り(約 5.5GB)、Python 環境・systemd(声・翻訳・ブリッジ)・管理アプリ・自動起動までを入れます。
宛先で一度だけ `sudo loginctl enable-linger $USER` と `sudo usermod -aG dialout $USER`(その後、再起動)を実行しておいてください。
このあと、StackChan を USB で挿すだけで、何も書き込まれていない新品は自動でファームウェアが書かれ、登録済みの機器はそのまま使えます。
新しい Arduino のスティックも、挿すと自動でスケッチが書き込まれます(Ubuntu 26.04 には `sg` が無いので、グループの反映には再起動が要ります)。

### 4. テスト
```bash
PYTHONPATH=bridge python3 -m unittest discover -s tests      # 約 4 分。`requests` が無い環境では 2 件のエラーは想定内
PYTHONPATH=bridge python3 tests/sim_lessons.py               # 授業のシミュレーション(SIM=silent|chain)
```

## 通信仕様(端末 ⇄ ブリッジ)
端末→ブリッジ: 先頭 1 バイトのタグ付きバイナリ `0x01`=PCM16LE 16kHz mono、`0x02`=JPEG。テキスト JSON は
`hello` / `dbg`(`cfps`=画面のコマ数、`cgap`=コマの最長間隔 ms など)/ `batt` / `event`(`touch`、`shake`、`chari_over`、`chari_mile` ほか)。

ブリッジ→端末(JSON):
- `{"t":"face","state":"listening|thinking|sad|happy|neutral|…"}` / `{"t":"caption",…}` / `{"t":"look",…}` / `{"t":"hush"}`
- `{"t":"speech",…}` → バイナリ `0x03`+PCM → `{"t":"speech_end"}`
- **画面ボード** `{"t":"board", "title","aw","ab","aa","bw","bb","ba","ai","bi","fx","foot","ms","st","am","bm","hl","cc"}`
  - `st` = `word|omikuji|riddle|mimic`、`am`/`bm` = `ok|ng|q|star|note`、`hl=1` で最後の字を赤く、`cc` = ラッキーカラー(RRGGBB)。
- **チャリはしり** `{"t":"chari","cmd":"start|stop|jump","body":true}`

## オフライン(インターネットなし)で使う
学校では Wi-Fi もインターネットもありません。このシステムは、動かすのに外のサーバーを必要としません。
- 声(VOICEVOX)・翻訳(Qwen3-4B)・聞き取り(SenseVoice)・顔検出は、すべて各 PC に入れたモデルが CPU で動かします。
- ブリッジは外部へ接続しません(接続先を調べて確認済み)。s109(GPU)に届かなければ、自動で PC 単体に切り替わります。
- 機器との通信は USB のみ。管理画面は `localhost:8080`、管理アプリ(Qt)も同じ PC の中だけで動きます。
- モデルの取得(`fetch_models.sh`)や環境の構築(`setup_host.sh`、`deploy.sh`)だけは、ネットワークが要ります。教室に持ち込む前に済ませてください。
- 複数の PC を同じ Wi-Fi に置くと、機器が別の PC のブリッジにも Wi-Fi でつながって、首の指示がぶつかります。USB だけで使う PC には、起動設定に `SC_USB_ONLY=1` を入れてください(Wi-Fi の接続を受けず、mDNS の告知もしません)。
- 機械学習ライブラリが勝手にモデルを探しに行かないよう、ブリッジの起動設定に `HF_HUB_OFFLINE=1` を入れています。

## 現状と未確認
- 2026-11-19 時点: 6 つの遊び、画面ボード、チャリはしり(画面・天面タッチ、からだジャンプ、処理落ち対策、管理アプリの代理ジャンプ)を実装。
- **実機で未確認**: 指でのタッチ・天面タッチ・からだジャンプの感度、カメラ距離の閾値。
- 2026-11-20: ゲーム中に通信が約 6 秒止まって切れる不具合を修正。原因は、複数の機器のスレッドが顔検出(OpenCV dnn)を同時に呼んで例外になり、USB の読み取りが切れていたこと
  (顔検出を排他にし、例外でも接続を切らない)。あわせて、チャリはしりの画面送信は描画タスク内に戻した(別タスクからの画面操作は SPI の排他を壊すため)。
  実機で 70 秒の連続ゲームを確認(コマ数 約 13/秒、コマの最長間隔 約 85 ms、通信の切断なし)。
- 画面を撮る機能(スクリーンショット)は、チャリはしり中は使えません。
- 韓国語の声は macOS の `say` 頼みのため、Ubuntu では出ません。

## 開発上の注意
- 画面を描くのは描画タスクだけ(別タスクから触ると SPI の排他が壊れて落ちる)。チャリはしりの送信専用タスクは、描画の完了を待ってから動く。
- 首は公式 StackChan-BSP(Feetech シリアルサーボ)で動かす。可動域は物にぶつからない範囲に。
- マイクとスピーカーは同時に使えないため、再生中はマイクを止める(半二重)。
- 工場イメージの作り方: `esptool.py merge-bin` で `bootloader.bin`(0x0)・`partitions.bin`(0x8000)・`boot_app0.bin`(0xe000)・`firmware.bin`(0x10000)を結合する。
- IP アドレス・Wi-Fi 情報・パスワードは、リポジトリや記録に書かない(`config.h` は git 管理外)。
